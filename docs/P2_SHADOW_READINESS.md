## Этап 4. Заключение

**1. Сохранилась ли инвестиционная гипотеза P2?**
Да, как гипотеза: «вход после нарушения major protected high и подтверждённого higher low, цель — структурный уровень
впереди цены». Конструкция цела: исправление 4H не изменило ни одного решения. На нетронутых активах P2 даёт
неотрицательный результат (+0,14R) там, где S2 v1.0.0 убыточна с интервалом целиком ниже нуля. Но положительное
ожидание после издержек **не подтверждено**:
- на нетронутых данных E[R] ≈ 0 с широким интервалом;
- при издержках ×2 — ноль;
- без лучшей сделки — отрицательно на DEV и на нетронутых данных.

Это профиль «редкие крупные выигрыши, частые −1R». Результат держится на правом хвосте, и выборки слишком малы,
чтобы его оценить.

**2. Изменилась ли эффективность после исправления 4H?**
Нет. На независимых активах результаты побитно совпадают (исправление действует только для истории с запуска).
На FABLES решения те же (WAIT), но структура теперь корректна, и известно событие, которое откроет вход.

**3. Остались ли конструктивные ошибки или недостижимые условия?**
Критических нет:
- полная конъюнкция условий достижима: 13 + 13 входов на 26 рядах;
- отказов риск-слоем и отменённых входов — 0, т. е. противоречия «стратегия ↔ риск-слой» нет;
- цель всегда впереди цены, стоп — под свежим HL.

Отмеченные слабости, а не ошибки:
- (а) P2 убыточна в боковике и падении — по построению это стратегия смены тренда;
- (б) на FABLES вход возможен только после нарушения 0.07975, т. е. сделок может долго не быть;
- (в) размер позиции при риске 1 % ≈ 55–60 $ — результат в долларах мал.

**4. Достаточно ли оснований для запуска SHADOW?**
Оснований для **вывода о прибыльности нет**. Оснований для **SHADOW как проверки вперёд по времени — достаточно**:
- конструкция корректна и структурно объяснима;
- на нетронутых данных P2 не хуже нуля и лучше действующей S2;
- SHADOW — виртуальный и изолированный, его стоимость — только инженерная.

Предлагаю запуск с заранее зафиксированными критериями (ниже) и с явной оговоркой, что на FABLES первые недели
вероятны без сделок.

**5. Какая архитектура нужна** — см. спецификацию.

## Этап 3. Техническая спецификация SHADOW-трейдера (к согласованию)

### Изоляция от основного бота

| Компонент | Решение |
|---|---|
| Процесс | Отдельный процесс `python -m tradinglab shadow` (новая подкоманда; `shadow.bat` для Windows). Основной `start.bat` не меняется; бот работает и без SHADOW |
| База | Отдельный файл **`data/shadow_lab.db`** (та же схема Store: experiments, trader_state, decisions, fills, trades, equity, events, controls). В `trading_lab.db` SHADOW **ничего не пишет** |
| Рыночные данные | **Только чтение** из `trading_lab.db` (`live_candles` 4H/1D, проверенные `quotes`) через отдельное SQLite-соединение `mode=ro`. Новых сетевых запросов нет — данные уже собирает основной бот |
| Эксперимент | Свой id `SH-P2-4H-<hash>-<start_ts>`; параметры и хэш правил записываются при START |
| Капитал | Виртуальные $1 000, только спот, только виртуальные сделки, ключей и транзакций нет |

### Стратегия (фиксированная версия)

- `tradinglab/shadow/p2.py` — **замороженная копия** правил P2 `research-0.1` → версия **`SHADOW-P2-4H 1.0.0`**.
- SHA-256 файла правил и параметров хранится в эксперименте. Любое изменение — новая версия и новый эксперимент.
- Режим и вход — структура v3 4H по **закрытым свечам** с `history="launch"` для FABLES. Старший ТФ 1D — только вето
  и только при определённой структуре. L2: внутрисвечные структурные сигналы не используются.
- Риск: risk-v1 4H (риск 1 %, экспозиция 0,8, лимит периода, Max DD 18 % → kill switch, cooldown), min_rr 1,5 —
  как в исследовании.

### Исполнение и Risk Monitor

- Решение — на закрытии 4H-свечи. Исполнение — по **первой проверенной котировке после решения**: тот же путь, что
  `ForwardRunner.on_bars` / `on_quote`.
- Исполнитель — `executor_from_db` → `LiveExecutor`:
  - **реальная комиссия hook** из StateView;
  - **многотиковая симуляция CLMM**;
  - проскальзывание, доп. проскальзывание стопа, газ.
- Уровни котировки: ONCHAIN / OFFCHAIN_ONLY / NONE и защита DEGRADED — как в FORWARD. При отсутствии надёжной цены
  вход отменяется, стоп исполняется по политике EXEC_POLICY.
- **Risk Monitor** проверяет стоп, T1 (50 %), trailing и time stop на каждой свежей котировке (`on_quote`), а не только
  на закрытии свечи.

### Управление и восстановление

- Команды START / PAUSE / RESUME / STOP / CLOSE / EMERGENCY — через очередь `controls` в `shadow_lab.db`.
  API `/api/shadow/*` — отдельные эндпоинты с тем же токеном и защитой localhost.
- Состояние трейдера (`to_state`) и журналы сохраняются после каждого бара и исполнения. После перезапуска —
  `load_state` + `hydrate`, обработка идемпотентна по `last_bar_ts`. Пропущенные во время простоя свечи — SKIPPED,
  сделок задним числом нет.
- Heartbeat процесса виден в интерфейсе. Ошибка целостности — PAUSE и предупреждение.

### Интерфейс: секция SHADOW LAB

- Отдельная страница/вкладка **SHADOW LAB**: статус, эксперимент, версия и хэш правил, кнопки управления.
- Позиция, ордера, сделки, решения с таблицей условий P2 и причиной ожидания; контекст структуры v3 4H (protected,
  что откроет вход).
- **Сравнение за одинаковый период** (от START SHADOW):
  - SHADOW P2 — нормированная кривая капитала;
  - S2 v1.0.0 из FW-1793900885 — только чтение equity 4H-трейдера основного эксперимента, перенормированная к той же
    дате старта;
  - Buy & Hold FABLES с той же моделью издержек.
  Таблица: доходность, Max DD, сделок, E[R], PF.
- Основные три трейдера и их страницы не меняются.

### Заранее зафиксированные критерии оценки

- Оценка — после **≥ 20 сделок или 120 дней** (что раньше). Метрики: E[R], PF, Max DD, доля прибыльных; сравнение

- Изменения правил во время эксперимента запрещены. Пересмотр — только новой версией.
