## 1. Что реализовано

| Требование | Реализация |
|---|---|
| S1: инициализация по major-диапазону | Границы — структурные экстремумы **уже известной** на этот бар истории. «Вся история» = все закрытые свечи до текущей, не больше. Направление задаёт первое закрытие за границей |
| S2: protected | Экстремум между пробитой major-границей и свечой пробоя. Каждое назначение, нарушение, кандидат и снятие хранятся в истории с причиной |
| Отсутствие look-ahead | Модуль **пошаговый по построению**: `Engine.step(свеча)`; пакетный прогон — тот же цикл. Решение по бару i использует swing, подтверждённые на барах < i, и цены ≤ i |
| Перезапуск | `to_state()` / `from_state()` (JSON) — продолжение побитно совпадает с непрерывным прогоном |
| Нарушение protected | По тени, без допусков: CHoCH + флаг `sweep`, если close вернулся. Новое направление при этом **не** подтверждается — состояние TRANSITION |
| Подтверждение | Отдельное событие: BOS с `confirmation`, закрытие за структурным экстремумом переходной фазы |
| AMBIGUOUS | Свеча пересекла уровни с обеих сторон: направление не выводится, protected снимаются, нейтральная TRANSITION; разрешается следующими свечами |
| Sweep | Один раз на уровень (major и internal) |
| Пропуски свечей | Не заполняются; события на первой свече после пропуска помечены `gap`; невалидные свечи отбрасываются и учитываются в `rejected` |
| Время | У swing — экстремум, подтверждение, назначение каждой роли. У события — свеча, `known_ts`, время первого касания тенью (`break_fact_ts`), триггер (high/low и цена), пробитый уровень и его источник, предыдущее состояние, причина |
| Major и internal раздельно | Internal — ZigZag 1,5·ATR, смена по закрытию за последним внутренним swing (iBOS/iCHoCH/iSWEEP). Legacy v1 (pivots 3/3, используется S2) и v2 показываются только как legacy |
| Уровни swing | `major` — получил структурную роль; `intermediate` — swing major-масштаба внутри major-диапазона; `internal` |
| Вторая форма подмены масштаба | Диагностика **SCALE_CONFLICT** (п. 4) и **HTF_CONFLICT**; конфликты показываются, но не разрешаются |

## 4. Вторая форма подмены масштаба: SCALE_CONFLICT

При последовательных BOS внутри одной вторичной волны protected переносится на мелкий третичный отскок. Обычное вторичное
восстановление затем даёт локальный major CHoCH. Правило ρ = 1/3 / K·ATR как обязательное **не внедрено**: оно не
прошло проверку переносимости.

Вместо этого:
- старший масштаб того же ТФ (k = 6·ATR — объявленный масштаб, а не порог значимости события) ведёт собственную
  major-структуру;
- если направление major расходится со старшим масштабом, у которого protected не нарушен, ставится **SCALE_CONFLICT**:
  на событии, в состоянии, отдельным маркером и в таблице.

Такой CHoCH/BOS **не считается подтверждённым разворотом внешнего тренда**; конфликт автоматически не разрешается.
Старший ТФ (4H для 1H) — отдельная пометка **HTF_CONFLICT**. При UNDEFINED/TRANSITION на HTF — «нет данных»,
подтверждения нет.

Сравнение способов — вложенные волны, 20 сидов: доля помеченных ложных CHoCH (выше — лучше) и помеченных истинных
разворотов (ниже — лучше):

| Способ | Ложные CHoCH помечены | Истинные развороты помечены | Комментарий |
|---|---|---|---|
| Цепочка protected в тренде | 72 / 73 | 9 / 12 | Не различает: в нисходящем тренде старшие LH есть всегда |
| **Старший масштаб k = 6 (выбран)** | **39 / 73** | **0 / 12** | Точный, но ловит около половины |
| Старший ТФ 4H | 73 / 73 | 8 / 12 | Ловит всё, но запаздывает и метит большинство истинных разворотов |

**Вывод:** SCALE_CONFLICT (старший масштаб) не даёт ложных тревог на истинных разворотах, HTF_CONFLICT даёт полноту.
Показываются оба. Около половины локальных CHoCH во вложенных волнах остаются **непомеченными** — это открытое
ограничение, а не решённая проблема.

## 7. Обновление панели на Windows без сброса FORWARD

FORWARD-эксперимент, свечи, решения и операции хранятся в `data\trading_lab.db`. Папка `data\` исключена из git
(`.gitignore`), поэтому обновление кода её не затрагивает. Новых зависимостей нет.

1. Закройте окно `start.bat` (или `start_web.bat` / `start_bot.bat`). Это пауза наблюдения: после запуска эксперимент
   продолжится с того же места, сделки задним числом не совершаются.

```bash
cd C:\TraderBot
```

```bash
git fetch origin claude/structure-v3-research
```

```bash
git checkout claude/structure-v3-research
```

```bash
git pull origin claude/structure-v3-research
```

3. Запустите `diagnose.bat` — он проверит зависимости и целостность базы (схема не менялась).
4. Запустите `start.bat` и обновите страницу браузера (Ctrl+F5, чтобы взять новый `app.js`).
5. Во вкладке «Структура» терминала 1H должно быть: «Major Trend DOWN», «Protected High 0.0797451 · PROTECTED».
   На графике — слои Major swings / Major BOS/CHoCH / Protected v3 / Фаза и диапазон.

**Не делайте:** не удаляйте `data\trading_lab.db`, не нажимайте STOP (это завершает эксперимент), не используйте

ветку стратегий (`claude/strategy-audit-research`) она не содержит.

## 8. Оставшиеся ограничения

1. **Зависимость от доступной истории.** Major-классификация FABLES опирается на первый минимум после запуска
   (0.05126). При старте позже вывод меняется (п. 3).
2. **Вторая форма подмены масштаба решена частично.** Около половины локальных CHoCH во вложенных волнах SCALE_CONFLICT
   не помечает. HTF_CONFLICT помечает всё, но запаздывает. Ни один способ не разрешает конфликт автоматически — так
   и задумано.
3. **Масштабы — исследовательские параметры:** k_major = 3, k_int = 1,5, k_senior = 6. Оптимальными они не объявляются.
4. **Задержка подтверждения разворота:** медиана ~109 баров в синтетике. CHoCH приходит раньше и показывается отдельно.
5. **4H/1D FABLES** — UNDEFINED из-за короткой истории (98 и 18 свечей).
6. **Порядок внутри свечи без тиков неизвестен** — AMBIGUOUS. Живая регистрация нарушения protected по котировке
   внутри формирующейся свечи пока **не включена**: события v3 строятся по закрытым свечам.
7. **Синтетика** — GBM и вложенные волны без толстых хвостов и гэпов: проверяет механику, а не реальную частоту.
