# FABLES Trading Lab

Исследовательская система **виртуальной (PAPER) спотовой торговли** FABLES/USDG (Uniswap v4, Robinhood Chain, chain id 4663).
Реальных транзакций нет: в коде нет приватных ключей, подписи и отправки транзакций.

Три независимых портфеля по $1 000 с разными стратегиями:

| Трейдер | Стратегия | Идея |
|---|---|---|
| 1H | `S1-1H-sweep-reversal` | отказ от пробоя минимума (liquidity sweep) с подтверждением денежным потоком |
| 4H | `S2-4H-structure-pullback` | смена структуры (CHoCH/BOS) и вход на откате в log-Fib зону |
| 1D | `S3-1D-range-breakout` | пробой диапазона накопления с объёмом и фундаментальными фильтрами |

Цель — проверить, есть ли устойчивое положительное ожидание после всех издержек и можно ли обойти Buy & Hold.
Гарантий прибыли нет; результаты на короткой истории FABLES помечаются `NOT VALIDATED`.

## Ключевые факты рынка (измерено 2026-11-05)
- Пул `0xcce8dcf7…a970869e` = `launchPoolId` официального конфига fables.fi; PoolKey сверен с poolId.
- Комиссия hook асимметрична: **покупка 0,5%, продажа 1,0%** (88 свопов, `evidence/fables_swaps/`).
- История: 1H — 376 закрытых свечей, 4H — 94, 1D — 16 (дневная стратегия в `WARMUP` до 30 свечей).

## Установка и запуск на Windows
1. Установите **Python 3.11+** с <https://www.python.org/downloads/> (отметьте «Add python.exe to PATH»).
2. Скачайте репозиторий (Code → Download ZIP или `git clone https://github.com/strace42-ai/Trader-bot`) на нужную ветку.
3. Дважды щёлкните **`start.bat`** — запускаются фоновый бот и панель в одном окне. Первый запуск создаёт `.venv` и ставит зависимости.
4. Панель: **<http://127.0.0.1:8770/>** (Performance — <http://127.0.0.1:8770/performance>).
5. Нажмите **START**: три виртуальных трейдера начнут торговать на живых данных FABLES с этого момента.
6. Закрытие вкладки браузера бота **не** останавливает. Остановка бота — закрыть окно консоли или `Ctrl+C` (эксперимент не завершается:
   после следующего запуска бот продолжит его с сохранённым состоянием).

| Файл | Что запускает |
|---|---|
| `start.bat` | бот + панель в одном окне (основной вариант) |
| `start_bot.bat` | только фоновый бот, без панели |
| `start_web.bat` | только панель (бот запущен отдельно) |
| `autostart_enable.bat` / `autostart_disable.bat` | **по желанию**: ярлык `start.bat --no-browser` в папке «Автозагрузка» пользователя (не служба и не задание планировщика) |

Параметры: `start.bat --port 8780`, `start.bat --no-browser`. Linux/macOS: `./start.sh`. Проверка источников без торговли:
`.venv\Scripts\python.exe -m tradinglab check`.

Интерфейс слушает только `127.0.0.1`; запросы с другим `Host` отклоняются (защита от DNS rebinding), управляющие команды требуют
токен установки (`data\control_token`, подставляется в страницу) и Origin этого же адреса (защита от CSRF).

### Что происходит при сбоях
| Ситуация | Поведение |
|---|---|
| Потеря интернета / сбой API или RPC | Новые свечи и котировки не появляются (ничего не придумывается). Котировка старше 3 мин недостоверна → новые входы запрещены; открытые позиции помечаются «без проверки», стоп не «имитируется», попытки продолжаются каждый цикл. Источник с 3 ошибками подряд временно пропускается (до 10 мин). |
| Компьютер выключен / спящий режим | Бот не работает — сделок нет. После пробуждения: загружаются пропущенные свечи; свечи, полученные позже окна актуальности (1H — 30 мин, 4H — 60 мин, 1D — 3 ч после закрытия), идут только в историю с решением `SKIPPED`. Открытая позиция сразу проверяется по текущей котировке (стоп исполнится по текущей цене, а не по историческим). |
| Перезапуск процесса | Портфели, позиции, отложенные ордера, журналы и статус эксперимента восстанавливаются из `trading_lab.db`; уже обработанные свечи не обрабатываются повторно, операции не дублируются. Команды старше 60 с не исполняются. |
| Пропуск нескольких свечей у источника | Пропуск фиксируется (`candle_gap`) и не заполняется; стратегия в окне с пропуском — `DATA_ERROR`, новых входов нет. |
| Скачок цены > 15% за минуту | Требует подтверждения следующей котировкой; до этого — ни входов, ни исполнения стопа по выбросу. |
| Расхождение пула (StateView) и DexScreener > 2% | Котировка недостоверна: новые входы запрещены, выход ждёт согласованной цены. |

Совет: для круглосуточной работы отключите в Windows спящий режим при питании от сети («Параметры → Система → Питание»).

## Панель
- **Верхняя панель (FORWARD · LIVE)**: живая цена FABLES (StateView/DexScreener) и её свежесть, статус проверки котировки, ликвидность и объём,
  статусы источников и бота, общий капитал трёх трейдеров, Net PnL, Buy & Hold и сравнение с ним (одна общая котировка),
  комиссия hook, газ, кнопки START / PAUSE / RESUME / STOP / EMERGENCY EXIT.
- **Режимы**: `FORWARD · LIVE` — живой эксперимент; `BACKTEST` — офлайн-бэктест на записанном наборе (`NOT VALIDATED`). Они не смешиваются.
- **Три терминала 1H / 4H / 1D**: живой график (закрытые свечи + формирующаяся серым + линия текущей цены), индикаторы, режим рынка,
  время следующего закрытия, последнее решение, позиция с уровнями входа/стопа/цели, кнопка CLOSE POSITION, Equity/Cash/FABLES/PnL,
  полный журнал (время сигнала, получения, решения и исполнения, ожидаемая и расчётная цена, fee/impact/slippage/gas, модель).
- **Объяснение решения**: таблица `Условие | Значение | Требование | Результат` (из тех же переменных, по которым алгоритм принимает
  решение), риск-фильтры, статистика причин отклонённых входов («что чаще всего мешает войти»).
- **Performance**: FORWARD — equity трёх трейдеров и B&H на общих timestamps синхронных оценок (раз в 5 мин), Net PnL, Max DD, Win Rate,
  Profit Factor, сделки, время в FABLES, отношение к B&H; BACKTEST — отдельно.

### Управление FORWARD
| Команда | Действие |
|---|---|
| START | новый эксперимент: неизменяемый момент начала, три портфеля по $1 000; B&H покупается по первой проверенной котировке |
| PAUSE | новые входы запрещены, отложенный вход отменяется; стопы, trailing и выходы продолжают защищать позиции |
| RESUME | снятие паузы |
| STOP | эксперимент завершается **без автоматической продажи**: отложенные ордера отменяются, решения и стопы больше не исполняются, позиции остаются и оцениваются по рынку |
| CLOSE POSITION | виртуальная продажа позиции одного трейдера по первой проверенной котировке (доступна и после STOP) |
| EMERGENCY EXIT | подтверждаемое закрытие всех позиций по первой проверенной котировке; RUNNING → PAUSED |

Все команды пишутся в журнал `controls` вместе с состоянием портфелей одной транзакцией.

## Структура
```
tradinglab/
  candles.py      закрытые свечи, дедупликация, пропуски (без выдуманных свечей)
  indicators.py   EMA/SMA, RSI, MACD, ATR, ADX/DMI, Bollinger, MFI, CMF, OBV, отн. объём
  structure.py    pivots, BOS/CHoCH, sweeps, EQH/EQL, FVG, S/R, log-Fibonacci
  divergence.py   подтверждённые regular/hidden дивергенции
  analysis.py     снимок на баре i, INSUFFICIENT_HISTORY, режим рынка
  strategies.py   три стратегии v1.0.0 с условиями ✓/✗ и объяснением
  execution.py    модель издержек (fee, импакт, slippage, газ), точность 18/6 знаков
  portfolio.py    Decimal, FIFO, инварианты учёта
  risk.py         risk-v1: лимиты, cooldown, kill switch, размер позиции
  engine.py       автомат состояний трейдера
  store.py        SQLite, append-only журналы, BACKTEST/FORWARD раздельно
  backtest.py     backtest без look-ahead + Buy & Hold с того же момента
  performance.py  метрики и синхронная оценка
  forward.py      Forward Scheduler, Risk Monitor, START/PAUSE/RESUME/STOP/CLOSE/EMERGENCY
  live/           сбор живых данных: transport, sources, collector, marketdb, clmm (модель исполнения v4), worker
  dataset.py      загрузка записанного набора данных
  web/            сервер FastAPI и фронтенд (vanilla JS, без сборки)
datasets/         записанные реальные данные (свечи GeckoTerminal, снимок DexScreener)
docs/             архитектура, спецификация стратегий, отчёты этапов
tests/            тесты
```
